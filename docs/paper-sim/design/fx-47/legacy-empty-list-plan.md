## 已复现的历史合同

PostgreSQL 18 与 psycopg-binary 3.3.4 的独立回执在同一干净合成提交上走市场包、`scan.run_scan` 和对应版本的写者。旧写者接受 Python 空列表 `[]`，保存原始整份 submission 的摘要，数据库报价的类型和文本分别为 `object`、`{}`。旧写者以相同输入重试返回原 ID。待修候选以相同输入走扫描入口或直接走 `record_scan` 均报 `papersim_scan_payload_conflict`，改用文本 `"[]"` 也报冲突。对照中，旧写者能写入空及非空的 JSON 数组文本。非空 Python 数字列表 `[0.1, 0.2]` 在旧写者的绑定处得到 SQLSTATE `42846`，该用例没有历史业务行。回执 SHA-256 为 `94a1de83e58effcf7a698a66c8bce7ff81b35c4a80163f824ee12fabff1ae919`。[隔离复现](fx47-legacy-probe/proof-v5.jsonl)

旧写者把候选原值交给 `%s::jsonb`。`ScanSubmission.payload_sha256()` 把原 `variant_quotes` 连同扫描、按序排列的全部候选、价格证据和入场字段序列化，Python 列表和文本在这份序列化中有不同的字节。待修候选新写入时绑定规范文本，预读时只对全为字符串的提交尝试原始整包摘要。来源为 `papersim/store.py:194,737–795`、`papersim/store_psycopg.py:392–399,414–511,526–535`，包解析与装配见 `papersim/scan.py:403,927,986,1020`。

## 同键行的完整摘要判定

生产改动限定在 `src/polymarket_alpha_lab/papersim/store_psycopg.py` 的 `record_scan` 写入边界。按现有校验取得原提交，并保有仅将每个 `variant_quotes` 改为规范数组文本的提交副本。新行存规范副本的整包摘要，逐候选把同一文本绑定为 JSONB 数组。空报价在新行上应读回数组 `[]`。沿用第 2 版的十进制精度、对象键序与数组顺序约定。

1. 对已存在的扫描键，先用规范副本的 `payload_sha256()` 对照库存摘要，再按需用原提交的 `payload_sha256()` 对照。原提交比较适用于全部通过校验的候选组合。这使旧写者接受过的逐项原样重试可直接出示原完整摘要，包含 Python 空列表与原拼写文本共存的扫描。
2. 两者均失配时，按已找到的 `scan_id` 一次读取各 `candidate_key` 以及 `jsonb_typeof(variant_quotes) = 'object' AND variant_quotes = '{}'::jsonb` 的布尔值。按键与提交中全部候选一一对应，保持提交的候选次序。凡该布尔值为真，只有本次报价规范化后恰为 `"[]"` 才可构造这条兼容路径，且只将该位置替换为 Python `[]`。任一标记位置收到非空报价，或候选键集不符，这条路径即失效。
3. 在其余位置，已提交的字符串取其进入 submission 时的逐字原值，Python 列表取本次输入的规范数组文本。计算由此形成的整份提交摘要。若仍失配，在已算好的规范副本上对同一组标记位置作同样的空列表替换，再比较整包摘要。这覆盖其余位置原本全为规范字符串而本次使用不同等值拼写的扫描。每种确定的整包形式至多比较一次。每份提交最多验证四种整包形式。
4. 任一成功分支的条件都是一个上述完整摘要等于库存 `scan_payload_sha256`。对象标记只选择可验证的空列表表示。其余报价文本来自本次输入，原包中的其他字段、候选与证据顺序都直接参与摘要。命中后以 `_read_back_candidates`、`_read_back_event_keys` 返回原 `scan_key`、`scan_id`、候选 ID 映射、现金事件键及 `inserted=False`。全部失配则抛原 `PapersimStoreError('papersim_scan_payload_conflict')`。已提交的历史扫描、候选及关联业务行只读，沿用现有字段、唯一约束与不可变表。

**交叉形式的可证范围。** 旧空列表遇到本次文本 `"[]"` 或 `"[ ]"` 时，解码可知本次恰为空数组，用 Python `[]` 重算才可命中旧摘要。旧规范文本遇到本次等值列表时，本次列表可生成那个规范文本。旧非规范文本的空格、键序和数字拼写只能由重试者提供，原规范化 JSONB 文本无法重建其提交字节。原字符串可通过原整包摘要或第 3 步保留原拼写的整包摘要。仅给等值列表、规范拼写或另一非规范拼写，应报冲突。新行的双向及等值文本重试均由规范摘要覆盖。[第 2 版合同及原生用例](fx47-plan-v2.md)

## 插入竞争与事务

保留现有事务中的扫描键预读。未命中时，扫描行的参数化 INSERT 使用 `ON CONFLICT (scan_key) DO NOTHING RETURNING scan_id`。只有拿到新 ID 的写者继续插候选、证据、入场和现金行。无返回行时，在同一事务内另发一条 SELECT 按该键读取获胜者的 ID 与摘要。在正常 READ COMMITTED 下，此语句可见刚提交的整次扫描，随后复用上述同一比较和 ID 读回路径。竞争者回滚时，等待写者按正常首次写入完成整单。不同扫描键撞上独立的 `operation_key` 唯一索引，或更强隔离级别要求事务重试时，由原数据库错误语义处理。参考 `papersim/store_psycopg.py:452–511,951–981`、`database/papersim/migrations/20261115000100_papersim_v2_core.sql:14,84` 和 `20261116000000_papersim_m2_operations.sql:138`。

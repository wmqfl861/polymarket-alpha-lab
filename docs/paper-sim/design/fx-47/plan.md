# FX-47 候选报价的原生写入与历史重放（修订 2）

状态为待原独立 ZCode 审者复审。对应 R6-7。源码基线为 `ab6edff2d64ac8aa5c2831d748b8730b63f8312d`，已有隔离复现记录 PostgreSQL 的 `42846`。本计划的验收均安排在计划 PASS 之后。

## 写入边界与重放契约（复审第 1 项）

唯一生产改动面是 `src/polymarket_alpha_lab/papersim/store_psycopg.py` 的 `record_scan` 写入边界。沿用 `store.py` 的校验、`ScanSubmission.payload_sha256()`、扫描键和现有参数化 INSERT。数据库结构、迁移、影子报价、策略阈值、样本、十变体、自检和冻结夹具均在本节点写入范围之外。

1. 先按现行规则校验原始 submission，保有原对象。只替换各候选的 `variant_quotes`，以冻结 dataclass 的副本组成写入用 submission。两种输入产生同一份**规范 JSON 文本**。字符串先解码为 JSON 数组，数组按现有非字符串 JSON 编码约定处理，对象键排序，逗号和冒号两侧无空格，保留数组元素顺序、字符串值和数值。数值文本的规范化须保全实际十进制报价；如读成浮点会损失末位，保留该数值的精确编码。其余字段沿用原值。以这个副本计算整次扫描摘要，并把副本中同一文本经现有 `_candidate_params` 绑定给 `_CANDIDATE_INSERT` 的 `%s::jsonb`。
2. 首次写入只存规范摘要与对应 JSONB 数组。已有同键行的预读先比规范摘要；不匹配且重放提供原有字符串时，另以未规范化的原 submission 调原有 `payload_sha256()` 比较完整历史摘要。命中任一完整摘要，返回原 `scan_id`、候选 ID、现金事件键和 `inserted=false`。其余情况沿用 `papersim_scan_payload_conflict`。兼容分支只读，事务仍包住扫描及其全部关联写入。不得只比报价、接受任意同键行、从 JSONB 猜原文或回填历史摘要。
3. 新行接受两种方向及等价文本拼写的重放。用**旧写者**存下的规范字符串行可用原字符串或等值数组重放。对实际使用非规范字符串写入的旧行，逐字节相同的原字符串仍可重放；等值数组、规范字符串或另一种非规范拼写均报原冲突。旧库留下的是整份提交的摘要和 JSONB，无法据此恢复原文的空白、对象键序等信息。对所有行，同键下改变一个报价、交换不同报价的元素顺序或修改另一负载字段都须冲突。

## 隔离原生验收（复审第 1、2 项）

测试只写 `tests/test_papersim_scan_store_native.py`。复用其独立新库和干净 Git 提交夹具，使用临时文件在同一路径写市场包，固定配置、队列、UTC 时间、`--operation-key`、`--attempt`、初始资金和空注册表。选择既会生成候选、又不建立仓位的有效拒绝样例（可复用过期盘口请求），确保第二次求值的组合状态相同。每次以真正的 `polymarket_alpha_lab.papersim.cli.main([...,"run-scan",...])` 进入，读取磁盘市场包，走原有装配、提供者、收据和 PostgreSQL 事务。

- **时钟。** `_cmd_run_scan` 在函数内 `import datetime as _datetime`。在测试中先以真实模块加载 scan、store、psycopg 及其日期适配器，再用函数作用域的 `monkeypatch.context()` 临时把 `sys.modules["datetime"]` 换成保留真实模块其余属性的代理。仅代理模块的 `datetime.now(tz)` 返回固定时刻并尊重时区。每次 CLI 退出即恢复。生产 CLI、数据库连接、市场包解析和写者均走原路径。
- **新行双向。** 在两个彼此独立的全新库分别做「非空字符串首次写入 → 同内容数组重放」和「数组首次写入 → 等值非规范字符串重放」，每库两次均退出 0。`inserted` 依次为 true、false；两次 CLI 输出的 `scan_key`、`scan_id` 和候选 ID 映射相同。每次命令后直接查库，`scan_payload_sha256` 等于规范 submission 的摘要，`jsonb_typeof(variant_quotes) = 'array'`，核对完整的有序非空内容。每组两次合计一行 scan、一行 candidate，同一 operation/attempt 的 `papersim.command_run_events` **恰两行**，分别为 STARTED 和 SUCCEEDED，后者指向同一 scan。两组摘要在各自固定的提交及扫描输入下比较。
- **旧行独立造数。** 再用两个独立新库，在测试内按修复前合同制作真实数据库行。用同包、同钟、同提交和当前空仓/注册表组装原始 submission，一组传规范的文本，例如 `[0.1,0.2]`，另一组传 `[ 0.10, 0.2 ]`。分别对未改写的 submission 调未修改的 `store.py` 方法取历史整包摘要；非规范组先断言该摘要与规范副本的摘要不同。通过参数化 SQL 在一个事务内插入带该键及历史摘要的 scan 行、直接将原字符串绑定成 JSONB 的完整 candidate 行和相应的价格证据。属于拒绝样例的 entry/cash 行计数为零。种子过程不调用修后的 `record_scan`。在 CLI 重放前先读回并保存 scan 键、ID、候选 ID、摘要原字节及 `variant_quotes::text` 的数据库字节；后者与原始市场包文本分别保留作比较。
- **旧行预期及负例。** 对两个历史库先以精确原字符串走 CLI，各退出 0，返回原 ID、`inserted=false`，与种子读回逐项相同。再以同内容数组重放，规范旧行退出 0 并返回原 ID，非规范旧行退出 1 并报告 `papersim_scan_payload_conflict`。后者再以另一文本拼写重试，仍报同一冲突。另在隔离用例中保持扫描键，分别改变报价、调换元素、改变另一个已纳入摘要的候选字段；对新行及历史非规范行检查真实内容的改变被拒绝，原摘要、报价和业务行计数保持种子或首次写入时的值。覆盖仅在浮点舍入后才看似相同的不同文本报价，以防规范化吞掉真实变动。失败命令的 FAILED 收据按现行合同记录，和上面的两次成功回执分组计数。

## 单写者与交接效力（复审第 3 项）

FX-47、NBA v2 和 FX-53/MO-2 对 `papersim/store_psycopg.py` 共用一个写入窗口，由协调者逐次交接。独立计划 PASS 后，开工前从刚合入的干净 `main` 记录精确基线、期间合并提交与改动符号。对照本次审核的 `ab6edff2` 检查 `record_scan`、`_candidate_params`、`_CANDIDATE_INSERT`、`store.py` 的摘要（含 `_candidate_payload`）和 `_cmd_run_scan`。其中任一处被期间的 NBA v2、MO-2 或其他合并修改，先将实际差异与更新计划交**同一原计划审者**重新取得 PASS，再开始实施。二次交接或重新基线时重复此检查。

在最终候选上运行上述启用原生 PostgreSQL 的聚焦用例、现有扫描幂等与候选重放测试，核对新增用例实际执行及 pass/skip 计数。按节点流程进行全量验证、编译、`git diff --check`、CodeGraph 同步和受跟踪内容敏感信息检查。独立代码复审核查完整摘要、旧行种子、CLI 入口、原生结果和冻结边界。登记候选提交、PR 头、每组运行的退出码/收据/SQL 读回、计划和代码复审原件路径、最终头三条绿工作流的运行编号及 `check_ci_merge.sh` 的 `CURRENT`；普通合入后回填实际合并提交。旧计划及 FAIL 原件原样保留。

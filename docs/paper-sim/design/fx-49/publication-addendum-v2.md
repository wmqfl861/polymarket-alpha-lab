1. CI 取平台本次 `pull_request` 的实际 base、head 和合并检出 G，确认 `HEAD=G`、G 的两个父依次为该 base/head，同时核对 PR 头自分叉点以来和实际合并树自 base 以来的改动。工作区读取直收文件，逐个与实际 Git blob 比较；本地 `--staged` 仅用于开 PR 前验证。与节点有关的清单、证据、精确属性、门禁及工作流变化均触发检查，增量缺失、删除文件或只改 CI 也不能走“无关改动”捷径。
2. 从同仓已归档 B 获得完整对象。固定 `refs/heads/handoff/sports-runtime-20261123` 只是已知位置，最终选择的是上表 B。用匿名只读方式展示既有受众在无需业务凭据或新仓库权限时能取得 B。取回的基线须有上表根树和唯一父 P。B 的原始 commit payload 为 450 字节，SHA-256 为 `cda09f641514d8dbdcf0b6f4034b5e980823ca8453d66354b13396c060acf902`。在一次性空 Git 对象库中只导入从 B 可达且连接完整的对象，完整核对 B 所需树和 blob；关闭替换对象、grafts、alternates、浅克隆、promisor/lazy fetch、钩子、子模块和外部过滤器。不要让现有 `new_checkout` 把主检出整个对象库作为运行库的 alternate。开工时断言运行库找不到 R，后续重建禁网络。若主检出恰已含 R，只能将可达集合过滤到 B 后才开始。主线候选和运行库有独立的 Git 索引与对象库。
3. 从 B 的索引启动。原清单精确包含 8 项直收、6 项行段增量、1 项 `.gitattributes`。直收由 G 工作区输入，和真实 PR 头的对应源码及固定 blob 互核；行段复用 `apply_delta` 的唯一键、类型、边界、顺序、LF 及逐行隐私预扫；运行属性按 B 自身原字节加原来那一条精确规则，主线属性按实际 main 基线分别检查。逐件核对原 blob/模式、最终 blob/模式、清单映射、增量摘要、固定脚本 ASCII/LF 和清单 SHA。`git hash-object -w --stdin` 不经过滤；临时索引 `write-tree` 必须给出 T。比较 B 至该索引的全部路径和模式，恰好为原 15 项，所有未改路径由完整 B 树继承。

## 五、留存、恢复和实际部署

持久发布物是普通 main 历史的具体 M、该 M 下的已审材料和已列入交接保留的 B。R 的所有新增信息都随这个 PR 进入正常仓库保留范围，读者按同一公开项目的 B 和 M 复现。不得以有期限的作业产物、本机共享对象目录、可改动分支尖端、未锚定 SHA 下载或裸的 HTTP 成功响应充当唯一交付物。发布记录列 B/M 的固定 OID、项目保留来源、材料路径及恢复方式。PR 头、标签或部署缓存可以消失，不改变算法。

基线保留与对象真实性分别验收。B 的 71 个新增文件及其公开交接清单、字节表在原保留历史中；B 本身不在主线候选的祖先链上。主线中的一个 B 哈希不能让 Git 垃圾回收器保留 B。先在不借本机共享库的空仓中从既有同受众归档完整取出 B；检查原交接清单和大小表作为数据，检查对象连接并生成脱敏回执。再用已获准的独立保留副本演练原保留引用不可用时的恢复。可对照 P 的主线历史，仅需保有 B 在 P 之上的既有对象和它们的准确字节，无需另备整个主线历史。在不同对象库断开首份来源及网络，以实际固定 M 或合并前等价候选材料重建、检出 B→R→B，核对每步的 HEAD、根树和受影响的实际文件。合并后用实际 M 再做一次用户视角的公开只读取件与复建。发布后继续沿用既有项目归档的保留及恢复责任；任何恢复的公开来源可见性必须与 B 相同。

若现有独立副本只在内部可读，要记录同受众如何在原位置恢复服务，并实证公开复读；不得将私有副本写成第二个匿名渠道。普通、已授权的同仓保留分支也可另存精确 R 作为独立恢复来源：先完成全套公开面预扫和节点发布门，再验证同一受众可取回；原交接分支不移动；CI 和用户侧重建均须另做一次移除这个辅助来源的成功演示。只将其当辅助保管。若审计包只有 B 的单次匿名可读、没有按项目保留并可恢复的对象实证，准确缺口是 **B 从原公开保留点失去后如何取回其完整闭包**。此时可以完成普通 PR 的实现、独立测试和三项托管检查，发布等强性标待验。无需为此引入新保护规则、改设置、把 B/R 的历史接到 main，或承诺抵抗管理员删库。若已有持久归档和恢复回执，直接复用并核实际对象。

生产软件交付只在适用授权后从固定 M 取材料、固定 B 取基线，在独立部署仓生成真实 R 并按完整 OID detached 检出；上一次实际检出、根树、文件模式、脚本源/清单/暂存/正式字节逐件核对。切换前实际基线应为 B；遇漂移记录实际 SHA 与差异并回到批准环节。回退使用实际记录的 B/经批准的先前对象及保护配置，以原业务锁和轮次边界进行，未决认领与回执保全。仓库只登记实际 M、R、部署实检 SHA、脚本 SHA 以及实际发生的操作。

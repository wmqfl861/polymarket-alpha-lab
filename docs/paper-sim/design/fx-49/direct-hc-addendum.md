## 四项条件及直达入口

1. **固定脚本。** Windows 系统 PowerShell 5.1 每次只启动同一脚本，唯一任务参数为 32 位小写十六进制 nonce。脚本按受保护清单定位原生 Hermes，在固定作业目录检查文件和目录句柄、重解析点、任务字段、实际正文文件的 SHA-256、UTC 窗口与余量。列举必须恰有一个 DM，`weixin:` 加原始标识的 UTF-8 摘要必须同时匹配只读本地绑定与既有业务绑定。原生发送前创建独占标记，原生发送最多一次。确认时要求退出码零、`success` 为真、平台为微信、消息编号有效，以及 **返回的 chat_id 确实等于刚核验的 DM 标识或其单次前缀形式**。固定脚本原子写回执和结果摘要。
2. **固定调用。** 修改运行层 `scripts/weixin_delivery.py` 的 `route`、`fixed_request`、退出解析及其调用点。生产 Linux 进程只用受保护配置指定的绝对 hc 路径及既有直连控制上下文。一次业务阶段的 argv 形式为 `[hc, "exec", "--json", "--on", 已核准的目标选择符, "--timeout", 本阶段限时, "-i", "--", 系统PowerShell绝对路径, "-NoProfile", "-NonInteractive", "-File", 固定脚本绝对路径, nonce]`。固定尾部仍由 `launcher(nonce)` 构造。阶段数据走有界标准输入。去掉远程中继、内层远程客户端及中继专用时限；用单个传输时限重算剩余额度，保留原生上限、UTC 截止、传输余量及读回执和清理的预留。任务不能选择进程、路径、地址、环境或附加参数。所有阶段都不拼远程命令、不内联脚本、不用 shell 或策略覆盖，不调用手工 skill、AI、会话客户端或宽松模式。
3. **远端执行权限。** 应用固定 argv 只能约束本应用；持有同一服务身份的一方可直接调用通用远程 API。v2 引用的公开 Herdr 源码说明通用 exec 按运行账户权限启动调用方传入的程序，未证明现场存在逐命令限制。原审包列明预期远端规则允许的系统 PowerShell、固定绝对脚本、严格 argv 和 nonce 语法，以及脚本、父目录、绑定和 Hermes 不能被该身份替换。先用离线版本文档、已提供的脱敏策略和适用身份／旁路覆盖说明核对。现场只在获准后读取权威配置，或使用策略引擎不执行命令的只读判定核对第二程序、额外参数和可替换脚本均被拒。没有这种证据时据实写明“不能证明只允许固定入口，通用执行及该账户已有文件能力仍可能可达”，由 owner 就此残余明确决定部署或停止。手工送达不表示接受该残余。不得试开 shell、执行负向探针、申请新权限或新增身份。
4. **业务防护。** 直连的控制上下文、目标机器指纹与主机名、私聊摘要、正文文件、时间窗、持久认领及独立核验均要有实证。保留现有账户、唯一私聊、消息类型、来源、频次和预算。禁止改绑、换路重发或扩大发送。去除双跳后，已撤去的中继指纹不再作为直达认证条件；不得把空中继字段直接判成核验成功。

## 直接目标与单层回执

在经部署方固定的 Linux hc 上下文，用本地只读 `hc machine ls --json` 查其直接可见的 Windows 目标。核准对象来自既有受保护配置，不能从手工投递结果、列表首行、显示名或任务输入学习。要求调用成功、完整 JSON、恰一条机器 ID 的摘要命中预期 Windows 指纹，且记录所报主机名与预期一致。用于每个 `--on` 的选择符须在同一上下文无歧义地绑定这条记录。优先采用该版本离线证实支持的完整稳定 ID；如版本仅能按名调度，须证实其实际解析规则、唯一精确映射及调度期间的绑定。别名冲突、默认或前缀歧义、上下文改变、无法证实绑定，均停止本次直达。用同一目标调用固定 `check`，Windows 自验主机名、部署脚本哈希与私聊，Linux 仅在固定协议、摘要及两个验证布尔值都正确时将现有 `check_route` 结果置真。后续使用同一已核准目标；恢复亦重新核对直达身份，不借中继枚举、另起远端身份探针或尝试其他目标。

每次 exec 解析一层 hc 传输封装。先验本地进程状态、输出上界和唯一键 JSON 对象，再验远程 `code` 是范围内整数，`timed_out`、`truncated` 均严格为假，`stdout` 能在上界内严格 base64 解码。远程码必须与已固定 hc 版本的本地进程返回约定相容，离线覆盖“本地成功并报告远程错误”及该版本若支持的“本地传播相同远程错误”；无证据的组合不接受。成功要求本地和远端均为零。解码后直接按当前 purpose 校验 Windows 结构、协议、脚本 SHA、码和成功字段。原双层包装、矛盾码、缺失、重复键或残缺数据不能记成功。保留已证实的 Windows 非零码，尤其 `32` 的现有三个明示拒绝类别；可信封装报 `32` 而拒绝体无效时沿用终止原因 `fixed_entry_refusal_unverified`。

`send` 返回 `sent` 仅准进入独立的 `receipt`。收据响应的 `contents` 是 Windows 协议自身的有界 base64，仍须解码并经 `verify_receipt` 和 `football_store.accepted_receipt` 对照已认领任务的 stage、nonce、正文版本及摘要、目标摘要、脚本与原生成功标志、消息号摘要和 `starts <= send_started <= confirmed < cutoff <= deadline`，并按既有容差对照数据库提交时刻。拒绝止于该任务，不能由陈旧收据翻转。超时、连接中断、非法封装、无回执或绑定不符，保留原状态或认领后的未确认；仅原来有资格的未知项可用既有一次只读恢复。

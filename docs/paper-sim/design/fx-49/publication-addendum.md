## 两个 Git 对象

运行基线 B 为 `bcce1b17f7263ab89859febfcb56188c295ab371`。计划通过后，在独立分支上以 B 为唯一父提交制作源码发布提交 R。其差异限于本节点的固定入口、业务接线与验收文件。R 经独立审核后由 CI 可读的专用受保护引用持久保存，权限沿用保留基线的可见范围。核对引用解析出的完整 commit 和 tree。保留交接分支的指向及其既有工作树均保持原状。本地已有基线对象；CI 能读取指定对象须在真实作业中验证。

主线 PR 从开工时的受保护 main 起分支。直接收录运行目录下的 `scripts/weixin_delivery.py`、`scripts/windows/Invoke-PaperWeixin.ps1` 和清单、精确路径的 `-text` 属性、无真实值的绑定样例、独立成员交付的 Windows 离线演练，以及根测试目录的 Linux 假传输测试。服务端仅依赖标准库，该测试可从正常主线入口收集并运行。此 PR 不接定时器、部署配置或业务库。FX-48 仍按其原节点开工。

同一 PR 在 `docs/paper-sim/design/fx-49/` 提供可阅读的运行增量与发布清单。增量覆盖运行目录的 `scripts/football_daily.py`、`scripts/football_store.py`、改动的已有回归和依赖运行树的新测试。清单列 B、R 的完整提交与 R 的根 tree、变动路径、Git 文件模式、原有及最终 blob、主线直收文件到运行路径的映射、增量与固定脚本的 SHA-256。两边的属性文件各自只加同一条精确规则。PR 只引入列明的直收文件、增量、验证入口及节点证据；禁止合并、变基或移植整个旧运行层到 main。

## 一次重建，三个验收入口

CI 检出实际 PR 源码，按清单读取 B 与 R 并验证父子关系。在临时 Git 索引从 B 应用增量、叠入直收 blob 和模式，核对全量变动路径及每个 blob，再用 `git write-tree` 比对 R 的根 tree。缺对象、额外路径或哈希不符即失败。仅为测试物化已预扫的依赖文件，在有 Git 元数据的隔离检出中确认 `HEAD` 为 R。服务端由此实际执行从部署提交核验清单与脚本的路径。只打无 Git 元数据的文件包无法覆盖该断言。

| 环境 | 常规 PR 必跑的检查 |
| --- | --- |
| Linux 假传输 | 在主线直收文件及 R 对应入口运行同一组无网络替身。检查固定 argv、完整正文、认领先于发送、并发与失败后发送次数、显式拒绝与只读恢复。 |
| Linux 独立临时 PostgreSQL | 用现有测试夹具起可丢弃的独立实例及合成旧行，走 R 的 `deliver_pregame_round`、`deliver_focus`、恢复与清扫。由另一连接观察提交顺序，验拒绝不重投、旧记录不误判、恢复上限和既有数据库结构。清除继承的数据库连接配置，仅对临时夹具初始化。 |
| Windows 离线演练 | 在隔离 CI 的 Windows PowerShell 5.1 用独立成员的演练入口、与 R 一致的脚本字节、精确生产 argv 及无网络替身跑 v2 六例。按表序核实退出码 `0/24/25/26/22/32` 与发送次数 `1/0/0/0/0/1`，仅首例取得接受回执。记录实测引擎和脚本摘要。 |

将这些检查挂入普通 PR 必经作业或其必需依赖，显式运行运行树专用测试。缺少引擎、临时库、演练器、用例或出现跳过，均不能计为通过。保留原三项 CI、主线全量、编译和冻结自检，按项目现行规则核验实际检出对象及 `check_ci_merge.sh` 的 `CURRENT`。独立 Linux 测试、代码及阶段审核绑定同一个 R 与实际主线源码候选。证据追加后重新核验源码、增量、清单及必需检查。

## 发布与交接

生成增量、选取基线依赖、写入暂存文件或输出测试结果前，在内存中对新增、删除、上下文和待输出内容做掩模预扫，诊断只报安全相对路径、行号和类别。不得落入真实基础设施资料、机器标识、端口、微信收件标识、正文或凭据，禁止上传整树、原始日志和未筛选输出。若只有旧删除行或上下文命中，以原文件完整 blob、行范围和已审替换字节表示该处增量，并核对最终完整 blob。新增字节有真实值时先修源并复审。提交前复查实际暂存内容。

普通合并后核对 main 实际落点 M 的直收文件和增量与被审源码一致，记录 M 与 R 两个完整提交。发布清单可预先写已实际生成的 R；M 产生后通过关联原节点的合并回执登记，避免文件自指。获准接触后，部署方须核实服务端实际检出 R、运行文件与 R 逐件一致，脚本源码、清单、暂存及正式字节一致。切换前仍须现场手动跑齐 v2 的 Windows 六例，并取得 v2 所要求的权限证据或 owner 对残余能力的决定，以及明确覆盖切换和单次真实验收的批准。仅按原范围下一条合格自然任务取一次脱敏回执。交接分别记录实际 M、R、服务端实检完整提交、脚本实测 SHA-256 与已发生的验收状态；未发生的项标待验，保持日常运行。

## 1. 改动边界

沿用现有发送账户、已绑定的唯一微信私聊、消息类型、正文来源、时间窗和业务范围。部署及 FX-48 首批合入前继续执行交接文档的范围冻结。四项改动各有对应的检查。

1. Windows 端新增 `scripts/windows/Invoke-PaperWeixin.ps1`（路径相对于运行层）和同目录的 `Invoke-PaperWeixin.ps1.sha256`。脚本适配 Windows PowerShell 5.1，源码只含 ASCII，固定换行，提交清单登记实际交付字节的 SHA-256。唯一任务参数为 32 位小写十六进制 nonce。正文、收件人、命令和路径均不能作为任务参数。
2. `weixin_delivery.py` 的 `launcher()` 只构造固定参数向量。生产调用的形式为系统 PowerShell 的绝对路径、`-NoProfile -NonInteractive -File`、固定脚本的绝对路径、nonce。安装时解析 Windows 路径并固定到受保护配置，运行时不依赖 shell 展开环境变量。去掉提示词、启动或恢复代理会话、代理输出解释、动态远程 PowerShell 字符串和宽松运行模式。路由检查、上传、发送、读回执、清理都经同一入口。
3. 核查远程权限是否真的收窄。公开上游 Herdr 没有提供这项命令白名单保证，核据、残余风险和部署决定见第 4 节。
4. 保留两跳机器指纹、主机名、私聊绑定、正文摘要、时间窗、发送前数据库认领、回执独立核验及拒绝后的终止行为。保留现有正文长度、预算和唯一性限制。新增协议不接收脚本片段、自定义程序、可选工作目录、额外参数、环境变量映射或任意文件名。

## 2. 两端协议与一次发送

**固定入口。** `check_route()` 和业务入口保持可用。Linux 仍以既有私有配置核对两跳机器指纹和预期 Windows 主机名。固定脚本每次执行均核对本机主机名与绑定预期值，可以在标准输入内传入规范化预期名称的摘要，调用结果仅返回核对布尔值。在绑定值、脚本摘要或已批准的原生客户端定位不可确认时关闭投递。

固定入口只接受有限的标准输入 JSON 请求。请求目的取自固定枚举，未知目的、额外字段、越界输入均拒绝。`check` 只核对脚本、身份、工具和私聊。`prepare` 只从标准输入接收现有任务元数据和正文，将 `job.json` 和 `note.txt` 写入受限任务目录并核验文件摘要。`send` 只读取该 nonce 已准备的文件。`receipt` 只读该 nonce 的回执。`cleanup` 只清理固定文件。所有操作共享完全相同的可执行文件和参数形式。`prepare`、`check`、`receipt` 和 `cleanup` 均无权触发发送。

**Windows 发出前。** 校验 nonce 与目录、元数据一致，限制请求大小和键，拒绝重复准备、现存的非任务目录、重解析点、可替换的父目录及正文文件。按原规则用无 BOM 的 UTF-8 写入完整正文，保留换行，按文件实际字节计算 SHA-256。任务目录固定在 `%LOCALAPPDATA%\PolymarketAlphaLab\WeixinDelivery\jobs\<nonce>\`。运行账号只需写入该作业区域。清理覆盖正文与元数据，短期保留已认领标记和回执以支持查证，覆盖有效发送窗及现有恢复/清理期限。项目持久认领仍由原 PostgreSQL 负责。

基线的 `ROUTE_CHECK` 已直接执行原生 Hermes 列举命令。基线只在代理提示词里描述原生发送命令，它的独立可用性和现有账户的发送权限仍须现场验证。固定脚本通过可信的 Hermes 绝对路径以参数数组执行。用 `send --list weixin --json` 检查平台集合恰有一条且为 `dm`。校验未加前缀的字符串标识非空，不含冒号、空白或控制字符。计算 UTF-8 的 `weixin:` 加该标识的 SHA-256，与原绑定摘要及任务摘要比对。安装方从既有私有绑定取摘要，在安装目录的只读本地清单固定这个摘要及 Hermes 可信绝对路径。清单由获准放置方维护，仅含必需的绑定数据，仓库只交付无真实值的结构。业务输入不能换绑。发送前再次检查这一私聊、正文摘要、UTC 时间窗和现有传输余量。Windows 在原子独占创建本次发送标记后、调用原生命令紧前记录 `send_started_at` 并检查 `starts_utc <= send_started_at < cutoff_utc`。标记已存在即停止。原生调用一次 `send --to <已校验的私聊> --file <该任务的 note.txt> --json`。真实标识只在进程内短暂用于原生命令，不进入任务文件、仓库或日志。使用既有客户端账户和原生平台授权。只要现有权限明确拒绝，就终止。

**Linux 认领与恢复。** `deliver()` 先校验路由并准备任务，再调 `on_submit`。只有同步持久化完成才能调 `send`。认领异常、被拒、时间窗改变或余量不足均不能启动发送。参数中的备用正文仅允许沿用既有的认领前选择。认领后禁止重投、换正文、换 nonce、换账号或换工具。Windows 拒绝、原生平台拒绝、要求对方先发消息、许可仍未满足都终止本次任务。超时、进程中断、回执缺失或无效保持未确认。仅非明确拒绝的旧有资格允许一次只读回执恢复。对显式授权拒绝，连恢复路径也不得据陈旧回执改判。拒绝发生在认领前时，调用方须抑制同一业务任务的调度重试。

`football_daily.py` 的两个正常投递入口及 `football_store.py` 的 `submit`、`finish_attempt`、`reserve_recovery` 都依赖旧代理会话语义。建议给 attempt 增加可区分旧记录和新固定投递的传输类型，老行读作旧类型。保持原业务键、原绑定校验、队列锁、并发排他与跨切换的在途认领保护。新单走“固定入口＋私聊摘要＋平台回执”的核验。既有本地会话绑定若仍用于轮次或排他，只留在原数据库端。不得伪造 `native_session_verified`、`native_turn_finished` 或给旧记录补认证。已有已认领或未知的尝试绝不重投。符合原恢复条件的旧尝试只允许固定脚本读取旧临时目录既定位置下的 `receipt.json`，维持原有会话核对和大小、重解析点限制。旧拒绝保持终止。新入口与两类遗留记录的兼容纳入 Linux 假执行。

**判定送达。** 要求原生退出码为零、顶层 `success` 为真、存在有效消息编号、平台为微信、返回聊天标识严格等于刚核验的标识或其单次前缀形式。只把消息编号摘要写入回执。Windows 用同目录原子写入发布 `receipt.json`，复制 `stage_key`、nonce、两个任务摘要、正文版本和截止时间，记录成功与聊天核对布尔值、原生退出码、开始及确认 UTC 时间。Linux 复用 `verify_receipt()` 和数据库的 `accepted_receipt()`，校验所有绑定及 `starts_utc <= send_started_at <= confirmed_at < cutoff_utc <= deadline`。解析 Herdr 两层返回时保留完整受控的失败退出码。拒绝、超时、截断、非零或不一致的封装不能作成功依据。原生命令的自由文本、标准错误、消息编号、聊天标识和正文不外传。

## 3. Linux 假执行与验收表

待正常计划独立审阅通过，原生开发角色实施。实际本机 ZCode 负责测试及独立验收。Linux 先完成全部离线工作，无须等待 Windows 放置批准。用假 Herdr、假 Hermes 和隔离的合成数据经过正常入口。在 Linux 沙盒内用校验过发行摘要的便携 `pwsh` 驱动**同一份**脚本。当前 Linux 的命令搜索路径未发现 `pwsh`，Python 编排假执行可直接开展。脚本实测若缺少运行时，须登记尚未执行，不能用另一种语言的重写替代。替身测试使用独立测试安装树，只部署无网络发送能力的替身，真实 Hermes 和真实凭据均不可见。生产定位不接受由任务控制的测试开关或程序路径。

以下为固定入口建议退出码，实施时冻结为 Linux 与 Windows 共同用例。替身计数只统计实际调用发送子命令，不含列举。失败诊断可在安全输出返回，不得产生可被认作接受的成功回执。

| 情形 | 固定入口退出码／原因 | 发送调用次数 | 回执和业务结果 |
| --- | --- | ---: | --- |
| 成功 | `0` | 1 | 写一份可核验的接受回执。数据库认领早于发送，核验后接受 |
| 收件人不唯一 | `24`，目标不唯一或非私聊 | 0 | 无接受回执。显式覆盖多条、零条和单条群聊 |
| 收件人摘要不符 | `25`，目标摘要不符 | 0 | 无接受回执。恰有一个私聊也不得更改绑定 |
| 正文哈希不符 | `26`，正文摘要不符 | 0 | 无接受回执。在准备后改变合成正文，触发发送前的实际文件校验 |
| 时间窗已过 | `22`，窗口关闭 | 0 | 无接受回执。包含恰等于截止时刻 |
| 发送命令拒绝 | `32`，原生明确拒绝 | 1 | 保留拒绝状态，无接受回执。随后调度、恢复和重复请求均不会触发第二次发送 |

联调时捕获假 Herdr 的两跳路由。机器清单沿用原控制面的只读查询，所有到 Windows 的进程启动均须为固定入口和合法 nonce。确认正文多行和特殊字符逐字节往返且不进 argv。验证双跳／主机名不符、认领失败、同 nonce 并发、认领后崩溃、原生命令已返回但回执未落盘、伪造／过时回执、旧未知与旧明确拒绝。用替身计数证明每种情况下最多启动一次。固定入口与服务端做静态扫描。确认没有调用代理客户端、旧宽松开关或任意远程 shell 文本。

## 4. Herdr 的实际权限与 Windows 放置门

Herdr 公开上游 `herdrdev/herdr-core` 的 `v0.1.22`（`6e2984629fcd600b0165f69b2e5b0bda5985ec1c`）在 `docs/security.md` 第 3–4 行说明 API 调用方可以用运行账户权限执行命令、改文件、控制终端。`crates/herdr-core/src/exec.rs` 的 `run` 第 133、153–161 行直接启动调用方提供的程序及参数。就此公开版本，不能登记“Herdr 原生支持逐命令白名单”。未查询任何在用主机、会话、配置或凭据。部署版本及操作系统是否另有独立限制均待核实。

运行层固定 argv 可以约束正常程序行为。能够经原 Herdr 身份直接使用通用 API 的服务端仍可能以 Windows 运行账户权限执行其他命令或读写其可访问的文件。单靠固定 Python 调用、脚本自报摘要、另建普通低权账户或只禁止写脚本，都不能证明整条链路只准一个入口。若现有部署具备独立于可修改客户端的受限端点，须确认同一服务身份没有并行的通用 Herdr 或终端权限。以受保护的配置和无副作用的反向授权检查，证明另一程序、脚本、额外参数以及改写固定入口均被拒绝。无此证据，按交接第 3 条向 owner 报告以上残余，不登记白名单达成。保持现有通道与原账户授权。不得借新通道、凭据、管理员身份或工具绕过任何拒绝。

1. **Linux 交付包。** 发布候选代码时，固定源提交、脚本字节、SHA-256、拟安装位置、原生客户端固定路径的配置来源、受影响的服务器调用方及六例结果。受保护的安装目录以 `%ProgramFiles%\PolymarketAlphaLab\WeixinDelivery\Invoke-PaperWeixin.ps1` 为建议位置，投递身份只读可执行。可写数据和保留回执使用第 2 节的用户作业目录。两处均使用系统解析的绝对路径。安装包不得带真实任务或凭据。
2. **仅在放置前取得 owner 明示批准。** 提供具体候选提交与 SHA、安装和回退动作、Windows 替身手测范围、同一既有私聊下一条合规消息的验收方式，以及上述权限证据或残余风险。若无法落实远端单入口，由 owner 在这次部署决定中明确接受该已报告残余，或要求先落实限制。只有明确覆盖相应范围后才接触 Windows。Linux 编写、假执行、正常只读计划与代码审阅不需要此批准。
3. **获准后放置与切换。** 在原投递通道暂停新认领并确认旧在途状态，保留账本和排他。按已审候选在 Windows 暂存脚本，分别用 `Get-FileHash -Algorithm SHA256` 核对暂存与最终文件对应的仓库摘要，检查安装目录、父目录与原生客户端对投递身份不可替换或改写。由获准安装方完成放置，运行账号不提权，不更改 PowerShell 执行策略。若系统要求签名，实际部署的已签名字节须同样经过审核并匹配清单。Windows PowerShell 5.1 在隔离的替身安装树至少手动跑一遍验收，建议一次复跑六例。归档脱敏退出码、替身次数、回执断言和脚本摘要。权限、摘要或现场结果不符即保持投递暂停。
4. **真实回执与登记。** 用下一条按现有业务规则自然产生、发送窗口仍开放、已授权给同一私聊且不属于旧拒绝或未知的任务，取一次真实回执。不得额外发探测消息或催对方先发消息。核验后仓库仅留脱敏公开投影（平台、核验结果、UTC 时刻、消息编号摘要等），不附正文、实际收件人、路由值、原始返回或私有绑定摘要。登记服务器**实际运行**工作树的完整 `git rev-parse HEAD`，核对投递文件与该提交一致，附上脚本 SHA、假执行证据、现场证据及真实回执相对路径。若无自然任务或取不到合格回执，真实投递项继续待验。回退是停止新投递、保留原认领和证据并回到最后获准的安全状态。不得重新启用代理或补发旧任务。

原交接中的受限代理退路仅在有证据证明原生发送技术上无法独立运行时另案呈报。权限拒绝、对方须先发消息、收件人不匹配或超时都不构成退路依据。另案须让 owner 知情并登记，仅容许既有的一条发送命令，代理只可见路径和摘要。默认实施和缺陷重试均不得进入该退路。

# FX-41 NBA v2 计划复审补遗

本补遗对应计划 SHA-256 `240f6153da3ff1a41625db89424bee537e662b0904abe4954491f84a6d3412ef`，由原独立 ZCode 会话 `sess_15e73061-c13d-4071-a325-56e6d566e427` 复审。原计划与原回执按原字节归档。

## 正式调用的前置条件与取证

1. 支持代码入 `main` 后核对实际执行 SHA、Git 树、三条 CI 的实际 checkout 和隔离合成计时回执。在最终支持树上，计算结束小于 3,540 秒、CLI 返回小于 3,600 秒，且双目标双侧的完整端到端预算有实测依据，方可将时钟门记为 `GO`。计时仍未证实或任一界限触及即停在正式命令之前。保存已测值、缺项或差额。
2. 同一干净执行 SHA、实例、应用角色、登记回执和科学键须贯穿登记、第二连接读回、只读预览与正式启动。既有登记绑定的提交与合入执行 SHA 冲突，或预览退出非零、任何复核值不符，立即停止并交回 owner。保留首次登记和原失败证据。
3. 正式命令仅由唯一执行者在确认 `not_run` 且时钟门为 `GO` 后启动一次，固定 `--attempt 1`。使用独立于操作终端的会话启动，记录唯一启动回执。原进程运行时以同一请求的 `--dry-run` 监测状态。预览看到既有认领时，转到原计划第 5 步核对原运行。
4. 分别留存登记、预览和正式运行的 stdout 与 stderr 原字节、各自字节数与 SHA-256、CLI 退出码、UTC 起止时间。监测预览可单独留档。出现错误时保存实际 reason code、阶段、已证明的开始及尝试事件 ID。原字节保存在私有证据区，库内引用仅记录合用摘要和定位键。
5. `RUN_FAILED` 取已封存运行和相连终态为准。按实际记录 `scientific_failure`、`budget_exhausted`、`budget_conflict` 或 `publication_veto` 的项目原因码及工件的 `budget.stopping_causes` 与 `budget.violations`。原根无合法封存、设置失败或提交确认未决，按各自观察状态记录并留空不存在的运行号与记分卡。

## 集成验收回执

1. 在最终候选回执中逐条列出规则来源测试的旧符号、新符号及继续约束的同一表达式，附原断言和新增的公共、受管入口委派断言。另列保留原检查的测试改名，并逐项处置 `test_weakening_scan.py` 报告。
2. 对草稿的 13 个 NBA 文件逐件核对 Git blob 与原审核附件。复用范围限于真实 PASS 回执已覆盖且字节相同的文件或明确片段。记录实际签字对象、附件 SHA-256、原始文件摘要和输出摘要。独立 ZCode 审最终候选、冲突处理及所有新增或实质变动。晚于最初的开发写权由协调者按文件逐次移交，最终对实际集成树验双方差异。
3. 从基线和最终候选分别运行交接指定的 `audit_static.py`，核不可达模块数和新增模块由正常 CLI 路径可达。保留空注册表下既有规则与结果的逐字节回归，与四个冻结夹具、自检、原评估锚点一起附实际回执。
4. 对新增行扫描和地址出现差异保存屏蔽后的输出。逐条解释类似联系人标识的命中在源码中的含义，另核新路径、提交说明、公开计划和回执的脱敏。验收结果以最终支持树为准。

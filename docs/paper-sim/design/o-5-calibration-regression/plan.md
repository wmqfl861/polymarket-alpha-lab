## O-5　从数值失败追到 CLI 和已提交的行

- 在 #114 审计对象上，`metrics.calibration_slope_intercept` 对单一结局、固定 logit、完全分离返回 `(None, None)`，混合且不可分的输入在数值预算内无法证明收敛时会抛 `ValueError("calibration fit did not converge")`。`scorecard.build_scorecard` 仅在二元分支调用它。`runner.execute_optimization_run` 的科学计算异常处理和 `store_psycopg` 的失败发布逻辑都需要真实调用才可验收。既有 `tests/test_papersim_optimize_metrics.py` 已覆盖零迭代的合法收敛与多加一项观测后不收敛的区别。保留四组已发布数值锚点和退化输入测试。
- 由实现者在既有原生运行器测试文件中增加一个精确回归。使用本机受管测试库、已登记的合成二元实验清单、足以实际调用记分卡的输入和正常 `optimize run --family … --as-of … --input-manifest …`。首选固定天然复现样本。若无可重复的默认预算样本，采用已有的混合、logit 重叠且非初始最优的数据和真 solver 的 `iterations=0`，在测试进程的记分卡调用点控制数值预算，并断言已命中真实二元分支及精确异常。用真实搜索/评分/运行器/存储/命令路径继续处理，避免直接在 CLI、存储或运行器入口伪造失败。受控预算的回执要标明故障注入条件。真实历史协议、校准容差、统计样本门槛和生产运行预算均不作调整。
- 从另一个数据库连接按同一个 `run_key` 核对正常结构化输出和退出码 `1`、一行 `optimization_runs.outcome='RUN_FAILED'`、同一 attempt 的一条 `STARTED` 与恰好一条 `FAILED` 终态、关联的运行及事件 ID、工件摘要和字节数，核验归档字节的 SHA-256。在 #114 的实现中预期外层错误码为 `papersim_optimize_scientific_failure`，内层 `pure.issue` 可保留确切原因及 `evaluation_integrity_failure`。登记实际契约，区分预算超时、非法清单与校准不收敛。检查零新候选/零角色事件/零前向判定、无半发布，且终态工件如实记载已完成的工作。重新提交完全相同的请求返回同一失败、相同 ID 与哈希、无重新计算及新增持久行。
- 若仅见未捕获异常、通用输入错误而无封存运行、悬空 `STARTED`、成功出口或重复终态，保留原失败，按实际缺口做最小运行器/发布修复，再经原复审者重审。若原流程已正确封存，交付测试和回执即可。由不同的本机 ZCode 执行原生测试及现有门禁，记录节点和相关 Linux CI 运行号。在实际落入 `main` 的版本上确认回归可从正常测试入口运行，并把实际 O-5 答案列入一期交接。

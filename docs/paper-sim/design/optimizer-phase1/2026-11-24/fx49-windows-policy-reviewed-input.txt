### 准入条件

机主或 Windows 管理员需要提供一份可核验的脱敏策略记录，说明在**同一获准目标、各自既有的演练及业务身份、系统 Windows PowerShell 5.1** 下，哪项正式策略允许以已审 `-NoProfile -NonInteractive -File` 调用执行固定脚本和演练器。记录须对应实际生效的作用域和适用身份。现有放置与演练守卫要求 `Process=Undefined`，并且有效值属于 `RemoteSigned` 或 `Unrestricted`。只要有效策略仍是 `Restricted`，已签名的脚本同样不能通过这条路径。维持该基线时，处置结论为继续阻塞。[当前守卫](../fx49-windows-rehearsal/windows.ps1#L158) · [已审计划第 4 节](../fx49-plan-v2.md)

若管理员提供已有组织签名流程及其对该目标有效的 `AllSigned` 策略证据，**当前守卫仍会在读取请求前拒绝 `AllSigned`**。这只能启动一次有明确范围的方案返审。返审须覆盖守卫对该策略的支持，以及正式脚本和演练器在精确调用下均具有系统认可、无需交互的可信发布者签名。当前业务脚本 `Invoke-PaperWeixin.ps1` 的 SHA-256 为 `e86beca8f4073da75a8bc1cd3aeef3e85230417c0b19f9424432e79baa7998c6`。Authenticode 签名会改变文件字节。须将最终签名文件入库，重建并核对 Git 对象、发布树、清单、演练工具的长度及哈希固定值，绑定新的独立计划、代码和阶段复审、Linux 验证及普通 CI 证据。后续现场交接须有独立于旧尝试的受审记录。[固定输入清单](../fx49-windows-rehearsal/OPERATOR.md) · [发布补遗](../fx49-publication-addendum.md)

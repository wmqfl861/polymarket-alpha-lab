# 04 模型自动优化：设计（2026-11-19）

这份文件说明"模型自动优化"要做成什么样、为什么这样做、守哪些边界。怎么分节点开发见 [05-development-plan.md](05-development-plan.md)。文中的接口、表结构和数字都是设计稿：接口和表结构在各节点的计划复审里定稿；数字（第 6 节）按 OD-J 登记之后冻结。

## 1. 要解决的问题

现在调模型是这样做的：有人（或一个代理）为某个联赛写一套脚本，在早期数据上试一批参数，在留出期上和原模型、和盘口比一比，写一份报告，再由复审决定要不要用。11-19 的四份联赛研究就是这样做出来的，一共 16 个脚本、4,086 行，各有各的调参、回测、指标和区间算法。

这样做有三个问题。第一，每次都从头写，口径不统一，没法持续跑。第二，回测上"调好"的参数到了留出期多半不比固定基线好：我重算 11-19 的新足球数据，30 个"赛事 × 盘口"格子里优化模型好过基线的只有 11 个，做了多重比较校正后只剩 1 个显著（见审核报告第 3.5 节）。第三，就算真有改进，从"研究结论"到"扫描用上新参数"之间没有受管的通道，也没有回退的办法。

"模型自动优化"就是把这件事变成一条受管的流水线：

1. 机器定期在历史数据上按固定的程序找候选参数，大多数时候的结论应该是"没有更好的"；
2. 找到的候选不直接上线，先在真实扫描里并行出预测但不下注（影子），和现役模型、和市场在同一批比赛上逐场比；
3. 达到事先写死的标准就自动换上去，换上去之后变差就自动换回来；
4. 每一步都入库、可重算、可追溯。

## 2. 范围：能调什么，不能调什么

| 能由优化器自动调 | 不在优化器范围内 |
| --- | --- |
| 各模型的超参数：衰减半衰期、先验强度（收缩）、低比分相关系数、Elo 斜率和主场优势、波动率窗口与估计方式、篮球的节奏与休息修正等 | 四个闸门阈值、入场价格窗口、十变体集合本身（冻结生产模型的定义） |
| 在同一类模型内部换一种估计程序（例如从"本季与上季混合"换成"指数衰减加层级收缩"） | 仓位档位、单队上限、初始资金、费率表 |
| 跨联赛强度表的赛季前重估（一季一次，赛季中不动，沿用 FX-17 的规定） | 晋级标准 OD-G 的六条数字和暂停规则 |
| 新联赛的历史回测与调参（只产出研究结论和建议） | 给任何联赛或盘口开放入场权限；任何真实资金、凭据、下单 |

为什么闸门阈值和仓位不能自动调：它们是"检验模型的尺子"。用结果去调尺子，等于把考试答案抄给考生，之后任何通过都不再说明问题。尺子要改，仍然走 owner 决定。优化器可以出一份"阈值敏感性"的描述性报告（换一个阈值会多几笔、少几笔），只供你看，不触发任何改动。

"模型"在这里只指模拟盘里的统计模型。V1 研究线里调用的大模型不在本设计范围内（OD-A 的现状是未激活）；第 12 节说明将来怎么接。

## 3. 核心概念

| 名称 | 含义 |
| --- | --- |
| **模型族** | 一类模型及其估计程序，例如"俱乐部足球·xG 泊松·冻结生产版""俱乐部足球·再校准估计器""国家队·Elo 泊松""NBA·节奏效率""加密·几何布朗运动" |
| **状态与超参数** | 球队评级、Elo、实现波动率这些随数据滚动更新的量叫状态，每次扫描本来就在变，不算换模型。半衰期、先验强度、斜率这些决定"怎么估"的量叫超参数，改了才算一个新的模型版本 |
| **模型规格** | 一个模型族加上一组确定的超参数、一组预先写死的敏感性变体（包络）、数据契约版本。把规格写成规范化的文本后取 SHA-256，就是它的身份。现行冻结模型是每个族内置的一份规格，叫基线 |
| **谱系** | 模型族 × 盘口类型 × 范围，例如"俱乐部足球 / 大小球 / 国内联赛"。业绩和角色都按谱系管理 |
| **角色** | 每个谱系任一时刻恰有一个**现役**（它的预测决定纸面入场）；有一个永久的**基线**（冻结模型，不当现役时也一直并行出预测，作为不动的参照）；最多两个**候选**（只出预测）；换届后的旧现役当一段时间**守卫**（用于判断要不要换回去）；被淘汰的标为**退役** |
| **优化运行** | 在一个固定的数据截点上，对一个模型族的搜索空间做一次完整的走前评估。结果只有四种：登记了候选、没有更好的、数据不足、运行失败 |
| **记分卡** | 对一份规格在一批比赛上的统一评分：对数损失、Brier、校准、对市场的配对差、变体离散度、拒绝数，以及各族原有的验证门 A–E |
| **晋级决定** | 按版本化的规则，对"候选 → 现役"或"现役 → 换回守卫"做的一次判定，连同当时的证据水位一起入库 |

入场权限和现役模型是两回事。一个谱系能不能下注，仍然由现有的暂停与准入政策和 owner 的决定管；优化器只决定"这个谱系用哪份规格出预测"。只做研究的谱系（国家队、NBA）同样可以有候选和现役，但不会因此获得入场权限。

## 4. 流程

```
              （每周一次）                         （每次扫描）                       （样本达到预定数量时）
 历史数据 --> 优化运行 --登记候选--> 影子并行：基线、候选、守卫       --> 晋级判定 --换届--> 新现役
 截点固定     嵌套走前验证          与现役在同一批市场上各出一份预测      按事先写死的规则        旧现役转守卫
              留出期只用一次        不下注、不动现金                       只看前向数据
                  |                        |                                   |                  |
              没有更好的             全部入库、可重放                     不达标：继续或退役     变差：自动换回
```

两个阶段各管一件事：

- **第一阶段（回测）只用来淘汰。** 候选必须在从未参与选参的留出期上显著好过现役，并且扛得住多重比较校正。过不了就没有候选。
- **第二阶段（前向）只用来确认。** 候选在真实扫描里并行足够多场，只要求"不比现役差"（非劣效），不要求再证明一次"更好"。原因是量。按 11-19 新足球数据里逐场配对差的离散程度估算（标准差：大小 2.5 约 0.066，胜平负约 0.13），要在前向数据上以 80% 的把握检出 0.01 的对数损失改进，大小球需要约 340 场，胜平负需要约 1,400 场。而"回测显著更好，加上前向不更差"这个组合，在同样的离散程度下把一个实际没用的候选被换上去的概率压到 1% 以下，需要的前向样本是 150 到 600 场。按每周扫描到 60 场左右估算，大小球类的第一次判定大约在第 3 周，胜平负在第 5 周。

## 5. 防过拟合的八条措施

1. **只做走前预测。** 每一场的预测只用当时已经结束的比赛。时间屏障由数据层统一保证（截点加完赛延迟），并且有一条固定的测试：往数据里加入当天及之后的比赛，历史预测必须一个字节都不变。11-18 修掉的国家队泄漏就是这类问题。
2. **嵌套选择。** 评的不是"哪组参数事后看最好"，而是"按这个规则选参数"这个程序本身在样本外的成绩。
3. **一倍标准误规则，向现役收缩。** 在所有与最优没有显著差别的参数组里，选离现役最近的那一组。离得一样近就选改动项更少的。选出来的还是现役参数，结论就是"没有更好的"，不碰留出期。
4. **留出期只用一次。** 选定之后，在留出期上对现役做一次配对比较，按比赛周（或比赛日）区块重采样，95% 区间上界小于 0 才算过。一次运行同时评多个谱系时，做 Holm 校正。没过的规格 28 天内不得再提。
5. **样本下限。** 样本不够就是"数据不足"，不出候选。下限见第 6 节。
6. **对市场基准如实报告。** 有同线、同时点市场价的子集上，同时给出候选、现役与市场三者的成绩。它不作为第一阶段的硬门槛（历史盘口数据不全），但会写进记分卡，并且在最终给 owner 的晋级评审材料里必须出现。
7. **预登记。** 候选登记的那一刻就写死：前向评估从什么时候起算、看哪一个主指标、几场时判、最长观察多久。到期没达标自动退役。
8. **限制看结果的次数和换届的频率。** 前向数据只在预定的两个样本点上各判一次，第一次用更严的阈值；其余时候只出描述性数字，不出判定。每个谱系 28 天内最多换届一次。

## 6. 规则 v1 的数字（建议值，按 OD-J 登记后冻结）

主指标是该谱系全部被评分市场的平均对数损失；配对差的定义是"候选减现役"，负数表示候选更好。区间一律按比赛键聚簇做重采样（同一场比赛的多条盘口线算一个簇），算法沿用评估模块已冻结的那一套。

| 模型族 | 第一阶段：留出期下限 | 第二阶段：前向下限（第一次判） | 最长影子期 |
| --- | --- | --- | --- |
| 俱乐部足球（大小球、两队进球、球队总进球） | 300 场，且不少于 20 个比赛周区块 | 150 场，且跨不少于 2 个完整比赛周 | 12 周 |
| 俱乐部足球（胜平负） | 同上 | 300 场，且跨不少于 2 个完整比赛周 | 12 周 |
| NBA | 300 场，且不少于 30 个比赛日区块 | 120 场，且不少于 14 天 | 10 周 |
| 国家队 | 300 场 | 60 场，且跨不少于 2 个国际比赛窗口 | 12 个月 |
| 加密 | 150 个已结算市场，且不少于 20 个到期日区块 | 60 个市场，且不少于 28 天 | 6 个月 |

| 判定 | 条件（须同时满足） |
| --- | --- |
| **登记为候选**（第一阶段） | 留出期配对差的 95% 区间上界 < 0（多谱系时经 Holm 校正）；记分卡上没有校准或验证门的回归；包络没有变窄（见下） |
| **晋级为现役**（第二阶段） | 前向样本达到下限；配对差的均值 ≤ 0；95% 区间上界 ≤ +0.005；"候选会下注的那些市场"的收盘价偏离均值不比现役低 1 美分以上（这类市场不足 30 个时只标注，不拦截）；没有硬性拦截 |
| **第一次没过** | 继续影子，到样本翻倍时判第二次（也是最后一次）。第一次判时把区间从 95% 收紧到 99% |
| **退役** | 第二次仍没过，或超过最长影子期 |
| **换回守卫** | 换届后样本达到前向下限时：配对差（新现役减守卫）的 95% 区间下界 > 0，即新现役显著更差；或数据完整性、验证门出现回归 |
| **硬性拦截**（任一成立就不换届） | 谱系处于暂停或自动停止状态；优化器被冻结；距上次换届不足 28 天；涉及赛季内冻结的参数；数据完整性门未过 |
| **改为请 owner 确认**（不自动换届） | 现役所在的队列已经累计 30 笔以上入场。这时换届会让一份接近攒够的晋级样本作废，值不值得由 owner 决定；判定照常入库，结论记为"晋级，待确认" |

**包络不能变窄。** 闸门里的"变体离散度不超过 6 美分"和"最差变体优势不低于 4 美分"是对着现行十变体的宽度定的。候选如果自带一套更窄的敏感性变体，等于变相放宽闸门。所以规则是：在同一批比赛上，候选包络的离散度中位数不得低于现役的 0.8 倍；低于的不自动登记，交 owner 决定。

**换届之后的两件事。**

- 评估模块按"模型版本 × 盘口类型 × 闸门版本"划队列，所以换现役等于开一个新队列，OD-G 六条的样本从头累计。这正是"在同一版下连续前向运行"的字面意思。自动优化不会让晋级更快；它的作用是让被拿去验证的那个模型更好（OD-L）。
- 暂停跟着谱系走，不跟着模型版本走。一个被暂停的谱系不会因为换了模型就恢复入场，恢复仍然需要人工复核。

## 8. 架构

新增一个子包 `src/polymarket_alpha_lab/papersim/optimize/`，全部是纯函数，除了通过现有的存储适配器之外不打开任何连接，不新增数据库连接模块，不新增第三方依赖（项目现在只依赖 `tzdata`，优化器只用标准库）。

| 模块 | 职责 |
| --- | --- |
| `optimize/spec.py` | 参数定义、模型规格、规范化文本与 SHA-256、模型版本字符串 |
| `optimize/families/base.py` | 模型族的统一接口 |
| `optimize/families/soccer_frozen.py`、`soccer_recalib.py`、`intl.py`、`nba.py`、`crypto.py` | 把现有模型包成模型族。冻结生产模型的源码不改 |
| `optimize/dataset.py` | 带"何时可用"时间戳的历史数据契约和构造器；泄漏防护 |
| `optimize/metrics.py` | 评分与配对区间。复用共享评分模块和评估模块已冻结的重采样，不再写新的一份 |
| `optimize/walkforward.py` | 折的生成（按完整比赛周或比赛日扩张）、嵌套选择 |
| `optimize/search.py` | 网格与逐维搜索、时间预算、一倍标准误规则、到现役的参数距离 |
| `optimize/scorecard.py` | 记分卡和验证门 A–E 的统一计算 |
| `optimize/policy.py` | 第 6 节的规则。纯判定，带规则版本号 |
| `optimize/registry.py` | 从角色事件推出"现在谁是现役、基线、候选、守卫" |
| `optimize/provider.py` | 扫描时按谱系给出各角色的规格。注册表为空或读不到时回落到基线 |
| `optimize/runner.py` | 一次优化运行的编排和回执 |

接口草案（实施时以节点计划为准）：

```python
@dataclass(frozen=True)
class ParamDef:
    name: str
    kind: str                      # "float" | "int" | "choice"
    default: object
    choices: tuple = ()
    lower: float | None = None
    upper: float | None = None
    season_frozen: bool = False    # True: only re-estimated before a season starts

@dataclass(frozen=True)
class ModelSpec:
    family: str
    procedure_version: str         # version of the estimation code, not of the parameters
    params: Mapping[str, object]
    envelope: tuple[Mapping[str, object], ...]
    data_contract: str
    legacy_model_version: str | None = None   # frozen baselines keep today's version string
    def canonical_json(self) -> str: ...
    def spec_sha256(self) -> str: ...
    def model_version(self) -> str: ...   # legacy string if set, else f"{procedure_version}+{spec_sha256[:12]}"

class ModelFamily(Protocol):
    family_id: str
    procedure_version: str
    def param_space(self) -> tuple[ParamDef, ...]: ...
    def baseline_spec(self) -> ModelSpec: ...
    def targets(self) -> tuple[str, ...]: ...                    # market types this family scores
    def fit(self, history, spec: ModelSpec, as_of: datetime): ...
    def predict(self, fitted, fixture): ...                      # None means an explicit refusal
```

两条实现约束：

- 规格的规范化文本里，数值一律写成十进制字符串，键按字典序排，避免同一组参数因为浮点表示或键的顺序得到两个身份。
- 现行两个模型版本字符串（`papersim/pipeline.py:117-118`）继续由基线规格原样给出，`policy_code_sha256()` 的值不变。注册表为空时，整个决策栈的输出必须和今天逐位相同；这一点用四个冻结夹具和自检的十项检查来证明。

## 9. 数据模型

在 `database/papersim/migrations/` 下新增一个迁移。六张表都沿用现有约定：只增不改，带三个纸面标志列和防改触发器，写入方只有 `select` 和 `insert` 权限，每张表有写入方的幂等键。

| 表 | 一行是什么 | 关键列 |
| --- | --- | --- |
| `papersim.optimization_runs` | 一次优化运行 | 运行键、模型族、谱系列表、数据截点、数据集摘要与清单（引用了哪些快照）、搜索空间摘要、规则版本、随机种子、试验数、预算、当时的现役规格、结果（四种之一）、记分卡、明细产物的快照校验值、代码提交号 |
| `papersim.model_specs` | 一份模型规格 | 规格校验值（主键）、模型族、估计程序版本、模型版本字符串、参数、包络、数据契约、来源（冻结基线、优化器、人工）、父规格、产生它的运行、代码提交号 |
| `papersim.promotion_decisions` | 一次判定 | 判定键、谱系、类别（前向判定、回退判定、人工）、候选与现役的规格、规则版本、第几次看、证据水位、指标、结论（晋级、晋级待确认、继续、退役、换回、保持、被拦截）、拦截原因、判定者 |
| `papersim.model_role_events` | 一次角色变更 | 事件键、谱系、规格、角色、生效时间、原因、前向计划（登记候选时必填）、对应的判定、决定者（`auto:规则版本` 或人名）、代码提交号 |
| `papersim.shadow_predictions` | 某份非现役规格对某个候选的一次预测 | 影子键、候选编号（指向现役在同一次扫描里为同一市场记下的那一行）、规格、当时的角色、概率、各变体报价、拒绝原因、"过不过闸门"及原因、假想成交价、时间 |
| `papersim.optimizer_control_events` | 一次冻结或解冻 | 控制键、范围（全局或某个谱系）、类别、原因、决定者、时间。解冻不能由自动规则写 |

影子预测挂在现役的候选行上，这样市场身份、决策时与收盘时的市场价、最终结果都复用已有的三张表，不必再存一遍；候选与现役天然是在同一批市场上配对的。

另外，候选表需要补两列（审核发现 N-1，修复项 FX-26）：`event_key`（比赛键；加密市场用"币种加到期日"）和 `event_start_at`（开赛时间）。评估和优化器都按比赛键聚簇；"收盘价必须早于开赛"也靠它才能核对。

每次优化运行的逐试验成绩和逐场预测可能有几兆字节，作为一份原始字节产物登记到现有的 `papersim.snapshots`，运行表里只存它的校验值。这样既守"业务证据只进数据库"的铁律，又能重放。

## 10. 与扫描闭环的接法

优化器的上线依赖 M2 的 `run-scan`（还没有实现）。为了不让 `run-scan` 写完再返工，约定在它动工之前先定下 `optimize/provider.py` 的接口，`run-scan` 从第一天起就通过它取规格：

1. 扫描开始时，按谱系向提供者要现役、基线、候选、守卫的规格。读不到注册表就全部回落到基线，并在扫描参数里记下"回落"。
2. 用现役规格出报价，走 `decide_entry`，照常写候选、入场和现金事件。候选行的模型版本取自规格。
3. 对其余角色各出一份预测，只走闸门的纯判定（不看资金、单队上限这类组合状态），写入 `shadow_predictions`。影子预测永远不产生入场和现金事件。
4. 重放包里带上规格的校验值和参数，`replay` 对现役的决定仍然逐位重算；影子预测可由快照加规格重算。
5. 换届只在两次扫描之间生效，不在一次扫描中途切换。

命令行在现有入口下增加一组子命令（按需导入，启动时加载的模块数仍须不超过 20）：

```
papersim.cli optimize families                     # list families, baseline specs, search-space summary
papersim.cli optimize run --family F --as-of T     # one historical optimization run (weekly)
papersim.cli optimize status [--lineage L]         # roles, forward sample counts, next look
papersim.cli optimize score --lineage L            # forward shadow statistics, read-only, descriptive
papersim.cli optimize decide --lineage L           # apply the rule at a scheduled look, write the decision
papersim.cli optimize apply --decision-id N        # write the role events of a PROMOTE/ROLLBACK decision
papersim.cli optimize rollback --lineage L --reason TEXT
papersim.cli optimize freeze|unfreeze [--lineage L] --reason TEXT
papersim.cli optimize report                       # weekly report for the status board
```

节奏：优化运行每周一次（周二，周末比赛结算之后）；影子统计每天刷新；判定只在样本到达预定点时发生；跨联赛强度表每个赛季开始前一次。

## 11. 安全边界

- **只在纸面上。** 新表都带纸面标志；子包里不出现账户、凭据、签名、下单相关的任何代码；守卫测试照常适用。
- **回落到基线。** 注册表为空、读取失败、规格校验值对不上、模型族版本不认识，任何一种情况都用冻结基线，并留下记录。不会因为优化器的故障停掉扫描。
- **一键冻结。** 写一条冻结事件，优化器就不再登记候选、不再换届；已有的现役保持不变。解冻必须由人来写。
- **不越权。** 优化器不能修改闸门、仓位、费率、晋级标准，不能给谱系开入场权限，不能解除暂停。
- **可重算。** 同样的数据快照、规格、种子和代码提交，重跑得到逐字节相同的产物。每次运行和判定都记录代码提交号。
- **有预算。** 每次运行有时间上限和试验数上限，超了就以"运行失败"收尾并保留已完成的部分，不静默截断。
- **变更可见。** 每次登记候选、换届、换回、退役，都进周报和状态板。

## 12. 没有采用的做法，和以后可以接的东西

- **不做"每周自动换成回测最优"。** 理由见第 1 节的数字。
- **不引入神经网络或梯度提升。** 现在每个谱系一季只有几百到几千场比赛，可调的自由度越多越容易拟合噪声；也不想为此引入重依赖。等某个谱系的前向样本过了几千场再议。
- **不把市场价直接混进模型概率（暂不）。** 把模型概率向市场价收缩通常能改善校准，但它会改变"优势"的含义，闸门的 4 美分和 5 美分就不再是原来的意思。这件事单独立项（MO-12），只写设计，由 owner 决定做不做。
- **大模型的预测（V1 研究线）。** 如果将来启用，把它登记成一个新的模型族即可：它的规格是"模型型号加提示词版本加检索配置"，同样走候选、影子、晋级这条路，评估口径完全一样。提示词或型号的自动搜索是另一类问题（每次试验要花钱、结果不确定），不在第一版范围内。
- **新联赛入池。** 第一版先把现有四个族做完。之后把 11-19 那四套脚本收拢成一条"新联赛评估"流程（MO-11）：给定赛果和盘口的数据源，自动产出记分卡和"只研究、可以影子、可以申请入场"三档建议。开放入场仍然是 owner 的决定。
